# Relational data model

## Conventions

PostgreSQL is the authoritative AppOps record store. IDs are UUIDs generated by application code; public display keys are separate. Timestamps use `timestamptz` in UTC. A local business calendar is a versioned policy input, not a database timezone change. Mutable aggregates have `version bigint NOT NULL` for optimistic concurrency. JSONB is reserved for versioned external payloads, validated policy parameters, and metadata with an explicit schema, not a substitute for core relations.

Every business table has `organization_id`. Application-scoped records additionally have `application_id`; environment-specific records have `environment_id`. Use composite foreign keys including organization scope so a child cannot refer to another organization's parent. Each referenced scoped aggregate exposes `UNIQUE (organization_id, id)`. The same principle applies to application/environment ownership where applicable.

Do not overwrite a vector with a different model or dimension. `embedding_profiles` records model identifier, immutable model revision, dimensions, normalization, query instruction, tokenizer version, and chunking profile. A profile change creates a parallel index generation; evaluate, publish atomically, and retain the old generation for rollback.

Publication is a transaction: validate review, completeness, media links, scope, and profile; switch the binding; increment `knowledge_epoch`; append audit and outbox records. Upload date does not determine the applicable version.

An outbox row and its originating business change are committed together. Dispatchers lease rows with short transactions using `FOR UPDATE SKIP LOCKED`. Never keep a SQL transaction open across a provider call. The unique constraints provide local deduplication; they cannot manufacture exactly-once behavior in a remote API.

## Initial indexes

Use B-tree indexes for `(organization_id, application_id, environment_id)`, membership checks, case state/owner/updated time, external ticket identity, and due outbox rows. Use GIN on a normalized `tsvector` for lexical retrieval and pg_trgm indexes only for explicitly supported identifiers and fuzzy title lookup.

Start vector retrieval with exact search within authorized scope; add HNSW only when a benchmark shows a need. Approximate retrieval with filters requires recall tests; enabling an index is not a permission control. Track index/profile generation explicitly.

## Transaction and security rules

The request or activity creates one unit of work and sets trusted organization/principal context with transaction-local settings. Use RLS for organization isolation, `FORCE ROW LEVEL SECURITY`, and a runtime role without table ownership or BYPASSRLS. Application/environment/audience authorization remains explicit in repository predicates and file delivery, with tests for both layers. Migration and maintenance roles are separate and never available to the AI.

Missing scope denies access. Reset pooled connection context transactionally; never use session-global tenant state. Audit insert failure rolls back a state-changing command. Runtime roles cannot update/delete audit rows; this is append-only access control, not cryptographic proof against database administrators.

Use optimistic version checks for case and policy edits; return a conflict rather than silently overwriting. Use bounded row locks for publication switches and action reservation. Migrations use expand/contract sequencing; production migrations require approval and a tested backup/restore path.
